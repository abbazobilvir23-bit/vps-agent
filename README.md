# vps-agent — личный агент на VPS

Репозиторий для персонального агента-разработчика, который живёт на твоём VPS
и работает в **изолированной песочнице**. Управление — позже через Telegram-бота.

## Что это

- **OpenCode 1.18.33** (`opencode run`) как ядро агента: нативные tools, реальное
  выполнение задач, git-история с откатом.
  Версия закреплена: линия **v2 не публикуется** в GitHub Releases (последняя
  публичная — `v1.18.33`), а официальный установщик не проверяет целостность
  архива и падает с `tar: Error is not recoverable`. Поэтому здесь свой
  установщик `install_opencode.sh` со скачиванием, проверкой gzip и тремя попытками.
- **Песочница** на уровне `permissions` в `workspace/opencode.json`:
  агент физически не может выйти из своей папки, не может трогать сеть,
  systemctl, docker, торгового бота и секреты.
- **Модель:** `openrouter/nvidia/nemotron-3-ultra-550b-a55b:free` —
  бесплатная, 1M контекст, нативный function calling. Стоимость задачи $0.
- **Автокоммит** после каждой задачи → любой результат откатывается git-ом.

## Почему не «просто дать агенту shell»

На сервере настроен VPN и крутится торговый бот. Цена ошибки — потерянный доступ
к серверу или остановленная торговля. Поэтому доступ构建 осознанно узкий:
белый список из `git`/чтения файлов и явный запрет всего, что трогает систему.

## Установка (две команды в консоли VPS)

```bash
git clone https://github.com/abbazobilvir23-bit/vps-agent /root/agent/app
cd /root/agent/app && bash setup.sh
```

`setup.sh` спросит OpenRouter API key (ввод не отображается, ключ не попадёт
в git и в историю shell) и создаст:

| Путь | Назначение |
|---|---|
| `/root/agent/workspace` | папка-песочница, свой git-репозиторий |
| `/root/agent/workspace/opencode.json` | правила доступа |
| `/root/agent/workspace/AGENTS.md` | инструкция агенту |
| `/root/agent/env` | секреты, права 600 |
| `/root/agent/session` | id текущей сессии |

Скрипт **не трогает** docker, systemd, сеть, `/etc`, `.bashrc` и каталог
`/root/mpf` торгового бота.

## Проверка

```bash
bash /root/agent/app/smoke.sh
```

Три теста: агент создаёт файл; опасные команды (`systemctl`, `iptables`,
`sudo reboot`, `curl`, `rm -rf`, `cat /etc/hosts`) отклоняются; чтение
`/etc/passwd` отклоняется. Если хоть один FAIL — агентом не пользоваться.

## Использование

```bash
bash /root/agent/app/agent.sh "Создай парсер CSV на Python"
bash /root/agent/app/agent.sh --continue "Добавь обработку пустых строк"
bash /root/agent/app/agent.sh --new "Другая задача"
bash /root/agent/app/agent.sh --status
```

## Интернет

- **Разрешено:** `webfetch` и `websearch` — агент ищет информацию и читает
  документацию. В `AGENTS.md` отдельно прописано, что текст страницы — это данные,
  а не инструкции (защита от prompt injection).
- **Запрещено:** `curl`, `wget`, `ssh`, `scp` в консоли. На сервере с VPN это
  риск: можно случайно снести маршрут или утянуть содержимое песочницы наружу.

## Telegram-мост

`bridge/bot.py` — только стандартная библиотека Python, ничего доустанавливать
не нужно. Полностью русский интерфейс с кнопочным меню.

Нижняя клавиатура (постоянная):

| Кнопка | Что делает |
|---|---|
| 💬 Общение | режим общения: читает файлы, ищет в интернете, **ничего не меняет** |
| 🛠 Код | режим задач: создаёт и правит файлы, каждая задача — коммит |
| 📊 Статус | режим, диалог, очередь, последний коммит |
| ⚙️ Настройки | модель, резервные модели, диалог |
| ❓ Помощь | справка |

Плюс инлайн-меню под сообщениями с **отметкой текущего режима** (✅) и быстрыми
действиями (статус, новый диалог, диагностика, помощь).

Команды видны в меню «/»: `/start` `/chat` `/task` `/status` `/new` `/stop`
`/diag` `/help`. При старте бот сам регистрирует команды, описание и кнопку
меню через BotFather API.

Во время работы показывается индикатор «печатает». В настройках и статусе —
инлайн-кнопки. Очередь и состояние диалога сохраняются на диске.

Проверка без Telegram (не трогает реального бота):

```bash
python3 /root/agent/app/bridge/bot.py --self-test   # 39 оффлайн-тестов
python3 /root/agent/app/bridge/bot.py --once "привет"          # чат
python3 /root/agent/app/bridge/bot.py --once --mode task "создай файл x.txt"
```

Особенности: очередь (одна задача за раз, остальные ждут), частичный вывод
(сообщение в Telegram обновляется по мере работы), состояние диалога на диске,
автоподъём через cron.

```bash
bash /root/agent/app/bridge/run.sh start     # запустить
bash /root/agent/app/bridge/run.sh status    # проверить
bash /root/agent/app/bridge/run.sh cron      # сторож в crontab
bash /root/agent/app/bridge/run.sh log 60    # журнал
python3 /root/agent/app/bridge/bot.py --self-test   # 28 оффлайн-тестов
```

## Ограничения (осознанные)

- Агент **не запускает** код: `python`, `node`, `pytest` запрещены. Он пишет
  код и говорит, что нужно проверить. Если нужна проверка — добавим
  изолированный исполнитель в контейнере без сети.
- `git push` запрещён — изменения остаются локально.
- Бесплатная модель: качество ниже платных, есть лимиты OpenRouter на число
  запросов в минуту.

## Файлы

- `setup.sh` — установка (идемпотентна)
- `install_opencode.sh` — загрузка OpenCode с проверкой целостности
- `agent.sh` — отправить задачу
- `smoke.sh` — тесты работоспособности и безопасности
- `workspace/opencode.json` — правила доступа (схема v1: объект `permission`,
  инструмент называется `bash`; порядок важен — последнее совпадающее правило
  выигрывает, поэтому catch-all `*` стоит ПЕРВЫМ, а частые запреты после него)
- `workspace/AGENTS.md` — инструкция агенту
- `bridge/bot.py` — Telegram-мост (stdlib, без pip)
- `bridge/run.sh` — запуск/стоп/статус/сторож в cron
- `install_opencode.sh` — загрузка OpenCode с проверкой целостности
